# 07. Response Format

## 1. Purpose

This document defines the output contract for conversion replies generated by the formatter.

## 2. Scope

The contract is shared across Telegram and Discord.
Platforms may differ in delivery mechanics, but not in the semantic structure of the rendered conversion reply.

## 3. Rendering Configuration

Expected formatter-level options:

```yaml
bot:
  show_usernames: false
  reply_to_original_message: false
  show_event_title: false
```

Meaning:

- `show_usernames`: include user names in grouped rows.
- `reply_to_original_message`: platform adapter posts the conversion as a reply to the triggering message.
- `show_event_title`: include per-block event title only if the LLM explicitly returned it.

`reply_to_original_message` affects delivery style only. It does not change the textual content.

## 4. Formatter Input Contract

For each time block, the formatter conceptually receives:

```json
{
  "event_title": "Deadline",
  "source": {
    "time_text": "12:00",
    "label": "London",
    "timezone": "Europe/London",
    "flag": "🇬🇧"
  },
  "rows": [
    {
      "label": "London",
      "timezone": "Europe/London",
      "flag": "🇬🇧",
      "local_time": "12:00",
      "day_shift": 0,
      "users": []
    },
    {
      "label": "Berlin",
      "timezone": "Europe/Berlin",
      "flag": "🇩🇪",
      "local_time": "13:00",
      "day_shift": 0,
      "users": ["@alice", "Bob Smith"]
    }
  ]
}
```

`event_title` is optional and must be absent or `null` unless the LLM explicitly returned it.

## 5. Core Output Rules

- one conversion scenario produces one atomic reply,
- multiple time points are rendered in one reply,
- time blocks are separated by a blank line,
- first row in each block is the source row,
- remaining rows are sorted by UTC offset ascending,
- the formatter does not decide whether a reply is allowed; it only renders valid input.

## 6. Basic Text Structure

### 6.1 Single Block Without Usernames

```text
12:00 London 🇬🇧
13:00 Berlin 🇩🇪
14:00 Helsinki 🇫🇮
```

### 6.2 Single Block With Usernames

```text
12:00 London 🇬🇧
13:00 Berlin 🇩🇪 @alice, Bob Smith
14:00 Helsinki 🇫🇮 @bob
```

### 6.3 Multiple Blocks

```text
12:00 London 🇬🇧
13:00 Berlin 🇩🇪

15:00 London 🇬🇧
16:00 Berlin 🇩🇪
```

## 7. Event Title Rules

If `show_event_title=true` and the LLM explicitly returned `event_title`, the formatter may render it above the corresponding time block.

Example:

```text
Deadline
12:00 London 🇬🇧
13:00 Berlin 🇩🇪
```

Rules:

- no title is invented by the formatter,
- no generic fallback title is generated by the formatter,
- no title is shown unless `show_event_title=true`,
- event title belongs to the block returned by the LLM point data.

## 8. Username and Name Rules

### 8.1 `show_usernames=false`

- grouped row contains no user list,
- if multiple users share the same timezone group, the row still appears only once.

### 8.2 `show_usernames=true`

- append names after the location segment,
- use comma-separated rendering,
- use display-friendly names,
- if a platform username exists and is appropriate, it may be rendered with `@`,
- if no username exists, use display name.

Canonical examples:

```text
13:00 Berlin 🇩🇪 @alice, Bob Smith
14:00 Helsinki 🇫🇮 Carol
```

## 9. Location Label Rules

Preferred rendering label:

1. human-friendly place label such as `Berlin` or `New York`,
2. if no suitable place label exists, fallback to IANA timezone name such as `Europe/Berlin`.

The formatter should prefer readability over raw system identifiers when both are available.

## 10. Grouping Rules

- users are grouped primarily by timezone,
- if multiple users in the same timezone have different city labels, those city labels may be joined in the rendered row,
- no duplicate timezone-group rows within one time block,
- source row is shown first even if its UTC offset would place it elsewhere,
- remaining rows are sorted by UTC offset ascending.

Example:

```text
13:00 Berlin, Munich 🇩🇪 @alice, Bob Smith
```

## 11. Day Shift Rules

Day-shift markers use superscript notation.

Canonical markers:

- `⁺¹` next day
- `⁻¹` previous day

Example:

```text
12:00 London 🇬🇧
20:00 Tokyo 🇯🇵⁺¹
```

## 12. Sparse Output Rules

### 12.1 Only Source Row Available

If no additional configured members are available for display, but a valid source row exists, the formatter may render only the source row.

Example:

```text
12:00 London 🇬🇧
```

### 12.2 Empty Input

If formatter input is empty after filtering, the formatter must return no reply payload.

### 12.3 Long Name Lists

If `show_usernames=true` and a grouped row contains many users, render:

- the first two names,
- then `+X more` for the remainder.

Example:

```text
13:00 Berlin 🇩🇪 @alice, Bob Smith, +4 more
```

## 13. Explicit Non-Rules

The following are not part of the current MVP output contract:

- footer such as `/tb_help`,
- automatic synthetic titles when the LLM did not return one,
- special compaction by "well-known capitals" when many timezones exist,
- platform-specific text format differences between Telegram and Discord.

## 14. Future Ideas

- adaptive compaction for chats with many distinct timezone groups,
- alternative summary rows for large audience outputs,
- richer event headings when LLM title extraction proves reliable.

ВЫВОДИ ТОЛЬКО JSON. БЕЗ ТЕКСТА, БЕЗ ПОЯСНЕНИЙ.

ЗАДАЧА:
Парсить из CURRENT MESSAGE всё точное время, которое можно однозначно извлечь.

ВАЖНО:
Используй наш канонический контракт ответа:
- верхнее поле: `event`
- массив: `points`
- в каждом point: `time`, `city`, `event_title`

Для этого prompt:
- `event = true`, если найдено хотя бы одно валидное время
- `event = false`, если валидного времени нет

JSON SCHEMA:
{
  "type": "object",
  "required": ["event", "points"],
  "additionalProperties": false,
  "properties": {
    "event": { "type": "boolean" },
    "points": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["time", "city", "event_title"],
        "additionalProperties": false,
        "properties": {
          "time": {
            "type": "string",
            "pattern": "^([01]\\d|2[0-3]):[0-5]\\d$"
          },
          "city": { "type": ["string", "null"] },
          "event_title": { "type": ["string", "null"] }
        }
      }
    }
  }
}

ПРАВИЛА:
1. ПАРСИМ, если время явное и однозначное.
2. Не морочим голову о координации или общем смысле сообщения.
3. `time` всегда в формате `HH:MM` (24-часовой).
4. `9 am` -> `09:00`, `3 pm` -> `15:00`.
5. Относительное время считай от `CURRENT TIME (UTC)`.
6. `через час` при `CURRENT TIME (UTC)=12:21` -> `13:21`.
7. `сегодня в 3` при `CURRENT TIME (UTC)=12:00` -> `15:00`.
8. Амбигуозное время без подсказки дня пропускай.
9. `в 3` без дополнительных подсказок -> skip.
10. `в 3 встречаемся` -> `15:00`.
11. Противоречия игнорируй.
12. `15 утра` -> skip.
13. `26:00` -> skip.
14. Одно событие с одним упоминанием времени -> один point.
15. Разные таймзоны одного события -> несколько points.
16. `9am EST, 2pm London` -> две точки с разными `city`.
17. Временные окна дают два точных времени.
18. `с 10 до 12` -> два points: `10:00` и `12:00`.
19. Не парси как время номера квартир, этажей, домов, суммы денег, счёты, номера задач, годы и даты.
20. Но контекст может переклассифицировать: `в 1500 встречаемся` -> время.

ПОЛЕ `city` МОЖЕТ БЫТЬ:
- город: `London`, `NYC`, `Москва`
- таймзона/аббревиатура: `EST`, `PST`, `UTC+3`, `UTC-5`
- `null`, если не указано

ПОЛЕ `event_title` МОЖЕТ БЫТЬ:
- `null`, если название события не указано
- кратким названием события, если оно прямо читается из сообщения
